01Introduction

AI is already part of the day

From unlocking a phone to finding the fastest way home, most of us rely on AI long before we stop to think about it.

  • It works quietly inside the tools we already use.
  • For computer engineers, it is both a subject to understand and a tool to build with.
  • Today: what it is, where we meet it, and how to use it well.

02Understanding AI

What is AI?

Software that performs tasks we normally associate with human intelligence: recognising patterns, understanding language, making decisions.

  • Machine learning learns from data instead of following hand-written rules.
  • Deep learning uses neural networks with many layers.
  • Generative AI produces new text, images and code.

Today’s AI is narrow: excellent at specific tasks, not a general mind.

03AI in Daily Life

Everyday examples

Most of the AI we use never calls itself AI.

  • Recommendations: what to watch, listen to or buy next.
  • Navigation: live traffic and arrival times.
  • Communication: spam filters, autocorrect, translation.
  • Phones: face unlock, voice assistants, sharper photos.
  • Banking: fraud checks on every card payment.

Example · Navigation

A maps app does not just know the roads. It knows how fast they are moving right now.

Data
Anonymous speed and location from phones on the road.
Model
Predicts how the traffic will change in the next minutes.
Result
An arrival time, and a new route when things change.

Example · Recommendations

The next video is not a coincidence. It is a prediction about you.

Data
What you watched, skipped and searched for.
Model
Finds people with similar taste, and what they enjoyed.
Result
A ranked list that is different for every user.

03AI in Daily Life

Benefits and risks

Benefits

  • Saves time on repetitive work.
  • Finds patterns people miss.
  • Makes knowledge and tools easier to reach.

Risks

  • Bias inherited from its training data.
  • Confident answers that are wrong.
  • Lost privacy, and relying on it too much.

04AI in Our Field

AI tools and use cases

For software engineers, AI has become part of the toolbox.

  • Writing code: assistants such as GitHub Copilot, Cursor and Claude Code.
  • Debugging and review: explaining errors, spotting bugs, suggesting fixes.
  • Tests and documentation: the work that often gets skipped.
  • Learning: unfamiliar code, libraries and concepts, explained.

04AI in Our Field

How LLMs work

A large language model does one thing: it predicts the next token, again and again.

  1. Tokenise: the text is split into tokens, small pieces of words.
  2. Embed: each token becomes a list of numbers.
  3. Attend: transformer layers weigh how the tokens relate to each other.
  4. Predict: the model scores every possible next token and picks one.

Example · One prediction

The capital of Türkiye is ▍

  1. Ankara93%
  2. Istanbul4%
  3. located1%
  4. a<1%

The chosen token joins the text, and the model predicts again. Values are illustrative.

04AI in Our Field

Basic vs. technical prompts

Basic

Write a method that reads a file.

  • Which language and version? Which file format?
  • Sync or async? What if the file is huge, or broken?
  • The model has to guess, so the answer is generic.

Technical

You are a senior C# developer working with .NET 8. Write an async method ReadOrdersAsync(string path, CancellationToken ct) that streams a UTF-8 CSV file line by line and returns IAsyncEnumerable<Order>. Skip malformed rows and log them with ILogger. Never load the whole file into memory. Return only the code, with XML doc comments.

What changed

Role
A senior C# developer, on .NET 8.
Task
One method, with its exact signature.
Constraints
Streaming, error handling, memory.
Output
Code only, documented.

Same model, far better answer.

04AI in Our Field

Token efficiency and accuracy

Tokens are the unit of cost, speed and memory. One token is roughly four characters of English.

  • Give the model what is relevant, not everything you have.
  • Structure beats length: clear sections, examples, the format you expect.
  • Break large tasks into smaller steps.
  • Check the result: run the tests, read the sources.

Example · The same request

Hello! I hope you are doing well. I was wondering if you could possibly help me out by writing, if it is not too much trouble, a C# method that would be able to check whether a given number is a prime number or not. Thank you so much in advance!About 60 tokens

Write a C# method IsPrime(int n). Return only the code.About 14 tokens

05Conclusion

Using AI responsibly

  • Verify: treat every answer as a draft, not a fact.
  • Protect data: no passwords, keys or personal data in a prompt.
  • Be transparent: say when AI helped, and follow the rules of your course or company.
  • Stay the engineer: you are responsible for the code you ship.

05Conclusion

Key takeaways

  • AI is already part of everyday life.
  • LLMs predict tokens; they do not know things.
  • Better prompts lead to better results.
  • It is a tool: powerful when used with judgement.
